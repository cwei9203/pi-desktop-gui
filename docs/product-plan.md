# 产品方案与功能范围

状态：初稿；更新日期：2026-10-22。

本文描述完整首期目标，不是当前版本的已实现功能清单。当前正在交付 M0/M1 的第一段实现，实际能力和限制见 [项目入口](README.md) 与 [开发指南](development.md)。

## 1. 要解决的问题

用户希望继续使用 Pi 的 Agent 能力，但需要一个更适合日常操作的桌面 GUI。当前明确取舍是减少首次连接步骤：选择项目即连接，自动发现 Pi，把手动路径和资源授权留在主动打开的高级设置中；缺失 Pi 时给出页面内安装指引。其余交互继续通过首版试用核对。

目标用户首先是项目作者本人：本地开发、多个项目来回切换、需要阅读工具输出和检查代码修改，愿意先在终端完成 Pi 安装与模型认证。

首版完成标准：能够连续完成「打开项目、发起任务、理解执行进展、追加或停止指令、检查修改、重启后继续会话」，无需为了普通对话操作返回 Pi TUI。

## 2. 产品原则

1. **内容优先**：让用户看到回答、当前动作和修改结果；细节按需展开。
2. **状态可信**：区分已发送、已接受、排队、执行中、等待输入、完成、停止和失败。
3. **可以干预**：运行中能追加指令、安排后续任务，也能停止并取回未执行的文字。
4. **会话连续**：重启后恢复历史和草稿，不自动重发可能已经执行的任务。
5. **边界清楚**：复用 Pi 生态；不把项目目录当作沙箱，不把工作区 diff 当作 Agent 专属修改。

## 3. 界面结构

默认采用桌面工作台布局，优先保证对话阅读宽度。右栏可关闭；窄窗口只保留主对话，侧栏通过按钮打开。

| 区域 | 首期内容 | 交互要求 |
| --- | --- | --- |
| 左栏 | 最近项目、当前项目的 GUI 会话、新建与重命名 | 展示项目路径；会话名称、更新时间、当前状态清楚可见 |
| 中间顶部 | 统一标题栏、会话名、项目和运行状态 | 窗口拖动与交互按钮区域分开，保留原生窗口控制；运行中禁用影响执行的切换 |
| 中间内容 | 用户消息、回答、推理内容（若 Pi 提供）、工具卡片 | Markdown、代码高亮、复制；推理和成功工具输出默认折叠 |
| 底部输入 | 多行输入、模型/推理级别、图片、发送、追加指令、排队、停止 | 中文输入法确认候选不误发；草稿按会话保存；当前已将模型选择放在输入区 |
| 右栏 | 工作区变更文件、只读 diff、刷新 | 明确已暂存、未暂存、未跟踪；缺少 Git 时不影响聊天 |

当前视觉方向：暖灰主背景、较深的窄侧栏、统一标题栏、克制的暖色操作按钮、细边框圆角输入区；对话保留阅读宽度，设置在工作区页面内打开，避免普通连接被弹窗打断。主题保留系统浅色/深色支持，具体密度继续试用调整。

信息结构参考 [Claude Desktop 官方改版说明](https://claude.com/resources/articles/claude-code-desktop-redesign) 的项目/会话侧栏与工作区组织；输入区与细边框参考 [官方预览、审查与合并文章](https://claude.com/resources/articles/preview-review-and-merge-with-claude-code) 中的 [输入区截图](https://assets.claude.com/470fca7b25e7ebc75147e83b641df5034d9d9be7.png) 和 [Diff 截图](https://assets.claude.com/75aa0f90a062a60b0cb99fd1ee6ea1b2daf5ee65.png)。静态图来自 2026 年 2 月旧版局部界面，改版说明发布于同年 4 月；这里只借鉴层次与操作密度，不声称一比一复刻或完全代表当前版本。终端、拖拽分栏等参考产品功能不因此加入首期范围。

## 4. 首期功能（P0）

P0 是交付范围；表中的验收标准均应验证，不能只实现正常路径。

### 4.1 启动、项目和会话

| 编号 | 功能 | 行为与验收标准 |
| --- | --- | --- |
| F01 | Pi 自动发现与引导 | 自动检测已保存路径、PATH 和常见 standalone/npm/Bun/Node 管理器目录；区分 ready/missing/unsupported/unavailable；当前固定支持 1.4.0，其他版本明确提示；失败时页面内提供官方固定版本 Release、可复制 npm 命令、Node 要求和重试，不要求向 GUI 提交密钥 |
| F02 | 项目选择与高级设置 | 系统目录选择后直接连接，最近项目一键连接；CWD 为所选目录，不弹二次连接确认；手工路径和项目资源批准放在主动打开的页面内高级面板；批准默认 false，仅用于本次指定项目连接，不跨项目隐式继承 |
| F03 | 会话管理 | 新建、重命名、列表、恢复 GUI 创建的持久会话；应用重启后会话仍可用；切换被扩展取消时保持原会话 |
| F04 | 模型与状态 | 从 Pi 获取可用模型与推理级别；空闲时切换并确认结果；显示 Pi 提供的 token、费用和上下文用量，未知值显示未知而非零 |

首期不扫描整个用户目录，也不承诺现有 Pi TUI 历史自动出现。已有会话导入列入 P1。不同项目运行资源需要重新加载，不能只切换会话文件而沿用错误的工作目录。

### 4.2 对话、执行和干预

| 编号 | 功能 | 行为与验收标准 |
| --- | --- | --- |
| F05 | 消息输入与渲染 | 多行文本、Markdown、代码复制、图片选择/粘贴和发送前预览；遵守模型图片能力，限制附件类型与大小；发送失败保留输入 |
| F06 | 工具执行展示 | 按 toolCallId 展示工具名称、执行状态、参数与结果；失败突出显示；长输出限制初始展示并允许展开，未知工具用通用视图 |
| F07 | 运行中消息 | 明确区分「追加指令」与「完成后执行」；前者在 Pi 允许的下一执行边界生效，不承诺立即打断正在执行的工具；以 Pi 队列状态更新界面 |
| F08 | 停止任务 | 清空待执行队列后中止当前任务；取回的文字可恢复到草稿，保留已有草稿；停止失败或进程退出必须显式展示，不自动重发 |

消息滚动规则：用户在底部时跟随新内容；用户上翻时保持阅读位置，显示「有新内容」。任务结束依据 Pi 会话级完成事件，不能把一次模型响应结束当作整个任务完成。

### 4.3 扩展、修改查看和桌面体验

| 编号 | 功能 | 行为与验收标准 |
| --- | --- | --- |
| F09 | 扩展基本交互 | 接住 select、confirm、input、editor，支持取消；显示通知和状态；扩展等待输入时用户有可操作入口，不出现静默卡住 |
| F10 | Pi 命令入口 | 列出 Pi 返回的扩展命令、模板和技能；按协议发送；不把 TUI 专属命令伪装成 GUI 功能 |
| F11 | 修改查看 | 展示工作区当前 Git 变更；文本 diff 可读；二进制/过大内容显示原因；不暂存、提交、回滚或自动覆盖文件 |
| F12 | 桌面可用性 | 键盘操作、焦点提示、中文输入、主题跟随系统、草稿恢复；启动和运行失败可恢复；退出时处理活跃进程，不留下无提示的后台任务 |

F09 的扩展交互属于兼容性必做项。自定义 TUI 组件不属于这一承诺；UI 需要说明限制。F11 只读指的是 GUI 的修改查看功能，Pi 的工具仍可以写文件或执行命令。

## 5. 关键流程

### 首次打开

1. 后台定位 Pi 并检查版本，页面显示安装状态；模型认证继续使用 Pi 配置，不要求先确认路径。
2. 点击「选择项目」并使用系统目录选择器；返回后直接连接。再次使用时，也可点击最近项目一键连接，不弹二次确认。
3. 若 Pi 缺失、版本不符或无法运行，在当前页面显示原因、官方 v1.4.0 Release、版本固定的 npm 命令及 Node.js 22.19.0+ 要求。完成安装和认证后重新检测，再选择或继续项目；GUI 不代为下载安装或登录。
4. 连接成功后创建或恢复 GUI 持久会话并读取模型；发送第一条消息时能区分连接、认证与模型执行失败。完整 P0 还包括推理级别与命令清单，当前尚未接入。

项目资源策略是 GUI 的启动选项。普通连接传入 `approve=false`；需要加载项目扩展、技能和配置时，用户主动打开「设置 → 高级设置」，针对当前项目勾选后点击「应用并连接项目」。授权不持久保存，提交后清除；编辑或切换项目、重新打开设置不会继承旧勾选。手工 Pi 路径只在高级提交时覆盖自动发现，默认空，连接成功清空，失败保留便于修正；成功连接使用的路径可保存为下次探测候选。首期不改写 Pi 的全局信任配置，信任也不代表工具被限制在项目目录。

### 执行与干预

1. 发送后先标记提交中，Pi 接受后进入执行或排队状态。
2. 持续展示回答与工具状态，收到扩展弹窗时显示等待用户输入。
3. 运行中新增文字，用户选择追加指令或完成后执行。
4. 点击停止后立即禁用重复发送，清队列并中止；结束后展示已停止或停止失败。

清队列返回的文字不保证包含附件，GUI 在本轮进程内需保留本地待发送消息与附件引用，明确恢复范围。Pi 没有稳定队列 ID 时不假装支持逐条撤回；首期提供整体清空。

### 切换与退出

1. 首期只允许一个活跃 Pi 进程。执行期间保持当前会话；切换前先等待完成或明确停止。
2. 关闭主窗口保留 macOS 应用及当前进程；菜单栏显示仍在运行，可重新打开窗口。
3. 真正退出应用时，若存在执行或排队工作，提供「停止并退出」和「取消退出」；不自动丢弃任务。
4. 崩溃重启后恢复会话历史，标记中断状态，保留草稿；由用户决定是否继续，不能自动重复执行工具。

## 6. 后续功能

| 优先级 | 功能 | 纳入条件 |
| --- | --- | --- |
| P1 | 导入已有 Pi 会话、会话搜索 | 明确旧会话迁移、跨项目路径与双进程写入策略 |
| P1 | 会话 fork/clone、分支浏览、手动压缩 | 基础会话恢复稳定；明确 fork 不回滚文件 |

首期之外：完整代码编辑器、内嵌终端、插件市场、可视化密钥管理、远程服务器、团队协作、云同步、自动 Git 操作、多 Agent 调度。遇到具体使用需求再重新排序。

## 7. 体验验收目标

以下是待测目标，不是已实现的性能结论：

- UI 收到事件后，正常负载下 100 ms 内呈现最新状态；允许合并文本刷新，不允许丢失协议事件。
- 1000 条消息的测试会话可滚动、定位最新消息并继续输入；超过渲染预算时采用窗口化展示，不能截断 Pi 的持久历史。
- 粘贴多行代码、中文输入法、展开长工具输出时，输入框不丢字、不误发。
- 非 Git 目录、缺少 Pi、无模型认证、断网、Pi 异常退出均有明确下一步，不出现无限等待。
- 用真实项目连续完成三次「发起、干预、看修改、重启恢复」流程，再宣布首版可日常试用。

## 8. 尚待用户使用反馈确定

默认先按本方案推进，不把这些选择变成启动阻塞：界面密度与视觉偏好、最常用模型和扩展、是否优先导入旧会话、是否有强烈的并行会话需求。M1 原型后用具体界面收集反馈。
