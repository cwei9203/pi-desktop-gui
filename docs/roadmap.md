# 开发路线与验收

状态：仅完成方案；所有实现任务尚未开始。更新日期：2026-10-22。

## 1. 交付顺序

先验证 MyGo 与真实 Pi 的集成，再实现日常使用闭环。下表估时按一名开发者、已有模型账号、每天约 6 小时有效开发计，是排期参考；框架缺陷和扩展兼容工作单独评估。

| 阶段 | 工作与交付 | 通过条件 | 参考时间 |
| --- | --- | --- | --- |
| M0 技术验证 | 固定 MyGo/Pi 版本；最小 WebView 窗口；RPC 收发；中文输入；停止与持久恢复 | 用真实 Pi 跑通一次带工具调用的任务；覆盖队列停止、崩溃恢复、进程退出；确认目标机器可构建 | 1–2 个工作日 |
| M1 对话闭环 | 项目选择、环境设置、会话创建/恢复、模型选择、消息与工具卡片 | F01–F06 主流程可用；中文输入与焦点不误发；错误能恢复；给出可交互界面供反馈 | 2–4 个工作日 |
| M2 日常可用 | 追加/排队、停止、扩展对话框、命令入口、Git diff、草稿、主题与退出 | F07–F12 通过；项目切换不串消息；扩展弹窗不导致永久等待 | 3–5 个工作日 |
| M3 自用试运行 | 长会话性能、故障演练、从 Finder 启动的本地 .app、真实项目试用 | 产品方案中的五项体验目标通过；记录限制和回归结果 | 2–3 个工作日 |

首版预算约 8–14 个工作日，不包含 Windows/Linux、签名公证、自动更新、旧会话导入或所有第三方扩展兼容。M0 若发现阻断问题，应先更新选型结论，再决定是否替换桌面壳；不要同时实现多个框架。

## 2. M0 最小验证清单

- [ ] 记录系统、架构、Go、前端工具、MyGo 和 Pi 的确切版本；从官方模板成功打开窗口。
- [ ] 从 Go 启动 Pi RPC，发送 get_state 和 prompt，实时展示文本与一组工具事件，区分接受与完成。
- [ ] 验证 clear_queue + abort、扩展 confirm/input、事件乱序响应、大于 64 KiB 的记录及半包读取。
- [ ] 验证正常退出、Pi 异常退出、工具子进程回收；重启后恢复同一持久会话，不重复发起旧任务。
- [ ] 在 WebView 验证中文输入、代码粘贴、图片剪贴板、长列表滚动；记录 .app 启动环境问题和实际资源占用。

验证结果应记录成功版本、复现步骤、失败限制与决定。M0 通过后再提交应用骨架；本次方案交付不创建占位业务代码或虚假的测试通过记录。

## 3. 实现阶段的测试重点

测试围绕会造成重复执行、消息丢失、错误状态或本机访问风险的行为，避免逐行复刻实现。

| 层面 | 必测场景 | 验证方式 |
| --- | --- | --- |
| RPC 读写 | 半包、多包、UTF-8 分块、CRLF、Unicode 分隔符、超长记录、乱序 response、stderr 混入诊断 | Go 单元测试 + 小型假 Pi 子进程 |
| 会话状态 | prompt handled、queued、agent_end 后自动继续、agent_settled、切换取消、旧进程晚到事件 | 记录官方事件形状的最小 fixture，验证状态转移 |
| 运行干预 | 清队列成功/失败、abort 超时、队列恢复保留草稿、等待扩展输入时停止 | 协议测试 + 真实 Pi 手动验证 |
| 数据与恢复 | 单实例与开发数据隔离、索引原子写失败、会话文件缺失、未落盘会话、压缩后历史、崩溃后不重发、正确 CWD | 临时目录集成测试 |
| UI 与 Git | 恶意 Markdown、链接隔离、中文输入、键盘可达、长输出、特殊文件名、无 HEAD、非 Git、二进制与符号链接 | 前端关键行为测试 + macOS 手动验收 |

在临时仓库运行真实 Pi 的写文件/工具测试，不向真实用户仓库执行破坏性测试。涉及模型请求的验证需使用已配置账号，记录成本和结果；假进程测试不能代替一次真实集成。

## 4. 首版验收脚本（人工）

1. 从 Finder 打开 .app，选择测试项目；创建会话并选择模型，发送带中文和代码块的任务。
2. 观察工具执行；上翻历史时仍保持阅读位置；追加一条指令，再排队一条后续任务，核对执行顺序。
3. 运行另一个任务并排队，点击停止；确认待执行任务未被 GUI 自动重发，文字可取回；触发扩展对话框并完成一次取消。
4. 查看已暂存、未暂存和未跟踪变更；确认标为工作区变更，GUI 没有修改索引或文件。切换到非 Git 项目后聊天仍可使用。
5. 重启应用恢复会话和草稿；模拟 Pi 进程崩溃再恢复，确认旧任务没有自动重复执行。

补充退出验证：执行期间关闭窗口，重开后任务仍可见；真正退出选择「停止并退出」，确认 GUI 管理的 Pi 及可确认归属的工具进程已回收。

## 5. 后续迭代顺序

1. 根据试用反馈决定会话搜索与旧历史导入的优先级，先验证迁移和单写入者策略。
2. 加入 fork/clone 和分支浏览，明确文件系统不会随会话分支回退。
3. 有真实并发需求后再引入多个 Pi 进程，单独处理同一目录同时修改的问题。
4. macOS 稳定后验证其他平台、Pi 分发、签名与更新，不从框架宣传直接推断发布质量。

## 6. 当前决定与开放问题

**当前决定**：本地目录名 pi-gui；macOS 优先；WebView + React/TypeScript；一个活跃 Pi 进程；复用本机 Pi 和认证；GUI 自己管理首期会话；Git 只读查看。

**尚未确认但不阻塞方案**：最终产品名、用户最常用的 Pi 扩展、视觉密度、旧会话导入是否必须提前、并行会话是否属于首版刚需。

**可能阻塞实现**：目标机器不能构建所选 MyGo 版本、所装 Pi 不支持目标 RPC、关键扩展依赖 TUI、无法可靠终止子进程。M0 应先解决这些问题，不靠追加功能掩盖。
