# 开发与运行指南

更新日期：2026-10-22。当前实现是 M0/M1 的第一段可运行代码，完整功能范围仍以 [产品方案](product-plan.md) 为准。

## 1. 环境

| 项目 | 当前版本或范围 | 说明 |
| --- | --- | --- |
| 操作系统 | macOS，Apple Silicon | 本轮构建环境；尚未验证 Intel Mac、Windows 或 Linux |
| Go | 1.27.1 | `go.mod` 指定版本，MyGo CLI 使用 `go tool mygo` |
| Bun | 1.4.3 | `package.json` 指定包管理器，依赖锁定在 `bun.lock` |
| MyGo | 0.6.2 | Go 依赖与前端 `mygo-runtime` 版本一致 |
| Pi | 1.4.0 | 当前连接代码只接受此版本，其他版本会给出错误 |

Pi 需单独安装并完成模型认证。GUI 复用 Pi 原有配置，不内置 Pi、模型账号或密钥管理。可从 [官方 v1.4.0 Release](https://github.com/earendil-works/pi/releases/tag/v1.4.0) 选择匹配系统与架构的 standalone 安装包，不要求额外安装 Node。也可使用版本固定的 npm 命令：

```sh
npm install -g --ignore-scripts @earendil-works/pi-coding-agent@1.4.0
```

npm 方式需要 Node.js 22.19.0 或更新版本。命令根据 [官方 Quickstart](https://pi.dev/docs/latest/quickstart) 加上当前 GUI 接受的 `@1.4.0`；[该版本 package.json](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/package.json) 确认包名、版本与 Node 要求。不要用未固定版本的安装或更新命令代替当前兼容版本。

先检查工具可发现：

```sh
go version
bun --version
pi --version
```

从 Finder 启动应用时，PATH 可能与终端不同。GUI 依次尝试已保存路径、PATH 和常见安装位置，覆盖 standalone、Homebrew、npm、Bun，以及 nvm、fnm、Volta、asdf、mise、nodenv 等 Node 管理器目录。探测总预算为 5 秒，单候选最多 1.5 秒，stdout/stderr 分别最多保留 4 KiB，候选上限为 128；不会扫描整个用户目录，也不读取或执行 shell 配置。

找到文件不等于能运行：npm 包装脚本仍需在应用继承的环境中找到 Node，自动发现不会重建 Node 管理器的 shell 环境。状态区分 `ready`（Pi 1.4.0 可运行）、`missing`（未找到）、`unsupported`（可识别版本不符）和 `unavailable`（权限、运行时、超时或输出异常）。自定义安装可在「设置 → 高级设置」填写 Pi 路径。

## 2. 安装依赖和启动

在项目根目录执行：

```sh
go mod download
bun install --frozen-lockfile
bun run dev
```

开发命令启动 MyGo 和 Vite，打开真正的桌面窗口。Vite 固定使用端口 5173；端口被占用时应停止占用它的开发服务，或同步修改 Vite 与 `mygo.json` 的地址。

首次使用：

1. 点击「选择项目」，在系统目录选择器中选择本地项目；返回后自动连接，不再打开二次连接弹窗。最近项目点击即连接。
2. 若 Pi 不可用，按页面内提示打开官方 v1.4.0 Release，或复制 npm 命令安装；在终端完成认证后点击「重新检测」，再选择或继续项目。普通连接无需填写路径；只有自定义路径或需要加载项目资源时，才主动打开设置中的高级面板。
3. 确认模型后发送任务。`Cmd+Enter` 发送，`Enter` 换行；输入法组合输入期间不触发发送。
4. 执行中可选择「追加指令」或「完成后执行」。停止时先清队列，再中止 Pi；已执行的文件修改不会回滚。

项目资源批准默认关闭。高级面板中勾选后，只在点击「应用并连接项目」时批准本次指定项目；连接提交后清除勾选，编辑/切换项目或重新打开设置也不会继承旧授权。手动路径覆盖默认留空，连接成功后清空，失败时保留便于修正；成功使用的 Pi 路径由后端保留为后续自动发现候选。路径覆盖与资源批准是独立选项；Pi 仍可访问当前用户有权限访问的项目外文件。

单独预览前端：

```sh
bun run dev:web
```

浏览器预览只用于样式与布局检查，页面会说明桌面连接不可用，不模拟 Agent 返回结果。

## 3. 生成绑定与打包

修改 Go 绑定方法后可单独生成 TypeScript 客户端：

```sh
bun run generate
```

`src/mygo.ts` 是生成文件。修改 Go 服务后重新生成，不直接编辑其内容。生成绑定不应启动 Pi 或写入用户设置。

构建 macOS 应用：

```sh
bun run build
open "build/darwin-arm64/Pi GUI.app"
```

当前 ARM64 输出：

- `build/darwin-arm64/Pi GUI.app`
- `build/darwin-arm64/Pi GUI 0.1.0 arm64.dmg`

输出目录、前端构建产物、缓存和依赖目录不提交到 Git。此次是本地构建，尚未配置 Developer ID 签名、公证或自动更新，不将 DMG 视为已完成公开发布验证的安装包。

## 4. 数据存储

| 内容 | macOS 位置或规则 |
| --- | --- |
| 正式应用数据 | `~/Library/Application Support/Pi GUI/` |
| 开发应用数据 | `~/Library/Application Support/Pi GUI Dev/` |
| 连接设置与会话索引 | 对应目录下的 `settings.json` |
| Pi 会话文件 | 对应目录下的 `sessions/<规范项目路径的 SHA-256>/` |
| 未发送草稿 | 当前应用 WebView 的本地存储，按会话或项目区分 |

开发与正式应用的数据分开，不能假设开发窗口中的会话会自动出现在正式应用中。项目路径规范化后作为索引依据；首期只恢复 GUI 管理的会话，不修改 Pi 的 TUI 历史目录。

设置和会话索引使用同目录临时文件原子替换，文件权限为 0600，新建父目录为 0700。设置读写上限为 4 MiB；损坏或超限文件会报错并保留原内容，不自动清空。遇到此类错误，先备份文件，再人工检查；不直接删除会话目录。

聊天正文由 Pi 保存，GUI 不复制认证信息。移除 GUI 设置不会撤销 Pi 已执行的操作，也不会删除项目文件。当前索引损坏后的自动重建与旧 TUI 会话导入尚未实现。

## 5. 测试

执行前端状态测试与 Go 测试：

```sh
bun run test
```

类型检查与 Go 竞争检查：

```sh
bun run typecheck
go test -race ./...
go vet ./...
```

只验证本机 Pi 握手，不发起模型任务：

```sh
PI_GUI_SMOKE_PI="$(command -v pi)" go test -run '^TestDesktopRealPiConnection$' -v .
```

此测试使用临时项目和临时 GUI 数据目录，检查 RPC 返回的会话状态与模型清单。它仍会启动本机 Pi，沿用用户级 Pi 配置；未设置 `PI_GUI_SMOKE_PI` 时默认跳过。握手成功不代表认证可用，也不代表模型请求、工具执行或扩展兼容已经验证。

现有测试重点包括：RPC 乱序响应、UTF-8 与大记录、清队列和停止、超时不重发、扩展输入、进程退出、设置原子保存，以及前端流式消息和最终消息的替换。快照回归覆盖未完成消息、活动工具和队列恢复，也覆盖发送请求等待扩展输入时，快照仍可返回，不被发送锁阻塞。空闲窗口重开和正常重启恢复已做原生应用验证；运行中停止/恢复、中文输入法和其余窗口行为仍需按 [开发路线](roadmap.md) 人工验证。

## 7. 已知限制

- 完整 P0 尚未完成：暂缺 Git diff、图片输入、推理级别设置、token/费用显示、会话重命名、技能与命令选择器。
- 当前仅接受 Pi 1.4.0，只支持一个活跃 Pi 进程。Windows 进程管理尚未实现；其他平台也没有本轮运行证据。
- 快照包含当前会话与 transient 数据，可恢复半条消息、活动工具和队列；压缩前完整历史、分支浏览、旧 TUI 会话导入、索引自动重建留待后续。
- 单条 RPC 记录上限为 32 MiB，文本输入上限为 1 MiB。transient 缓存上限为 16 MiB 或 16384 条记录，超限会明确报错，等待任务结束后刷新；长对话内存、1000 条消息滚动和剪贴板图片尚未完成验收。
- 基础 select、confirm、input、editor 可映射到 GUI；依赖终端自定义组件的扩展不兼容。stderr 当前持续消费以避免阻塞，但尚未提供完整诊断日志查看。

关闭主窗口与退出应用不同：应用可保留 Pi 进程，重新点击 Dock 打开窗口；真正退出时清理 GUI 启动的 Pi 进程。正常 `Cmd+Q` 退出、正常重启恢复和空闲窗口重开已验证；运行中窗口重开、停止和退出仍需完整桌面实测。GUI 不提供沙箱，项目选择也不限制 Pi 访问其他可读写路径。

高级设置中的目录选择只更新待连接的项目，保留手动 Pi 路径；点击「应用并连接项目」才提交。主界面和最近项目仍直接自动连接。
